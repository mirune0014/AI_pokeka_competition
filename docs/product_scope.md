# PTCG Human Client MVP 製品スコープ

## 目的

本製品は、Windows 11 上で人間が任意の 60 枚デッキを使い、自分で管理する Kaggle 互換ローカルエージェントと対戦するローカル GUI クライアントです。

製品の主軸は、カードゲームとして操作できること、対戦中の非公開情報を人間側へ流さないこと、実行したエージェントの内容を SHA-256 で識別できることです。

## 取り込めるエージェント

実行ルートに `main.py`、`deck.csv`、`cg/__init__.py`、`cg/api.py`、`cg/sim.py`、`cg/utils.py`、`cg/game.py`、`cg/cg.dll` を持つパッケージを対象とします。

入力形式は、ルート直下に前記ファイルを持つ `.tar.gz` または展開済みフォルダーです。

外側の管理用フォルダーから実行ルートを再帰的に推測しません。

`requirements.txt` に基づく依存パッケージの自動インストールも行いません。

## MVP に含む機能

- PySide6 と Qt Quick/QML による Windows ネイティブ GUI。
- 対戦準備、対戦盤面、結果、リプレイの 4 画面。
- 自己管理ローカルエージェントの内容登録、改変検知、起動互換性確認。
- 保存済み submission 55155015 と一致した場合の提出物本人性表示。
- CSV からの人間用 60 枚デッキ読み込み。
- カード ID、枚数、60 枚構成、両座席でのエンジン初期化受理の段階別検証。
- 人間の Player 0 または Player 1 への配置。
- 先攻選択を含む、現在選択者に従った全局面処理。
- 汎用合法手パネルによる単一、複数、順序付き、0 件選択。
- 対戦ごとの新規 spawn 子プロセス。
- UTF-8 JSON の明示的なローカル IPC。
- 固定人間席向け `HumanViewState` と公開ログ。
- 放棄、AI 側の技術的敗北、システム障害、最大ステップ到達の分類。
- 初期状態と各受理済み `battle_select` 後のスナップショット型リプレイ。
- ユーザー指定の外部カード画像、日本語カード名、日本語ワザ名のカタログ。
- Kaggle の人間用対戦ビューワーに近い緑色の盤面と、固定表示の大型カードプレビュー。
- 数値 HP、HP バー、ついているエネルギー、ポケモンのどうぐ、右側トラッシュの表示。
- AI 行動後の表示待ち時間と、日本語の直前行動表示。
- サイド固有の選択名、合法手番号の盤面対応、選択済みカードの着色、エネルギー付与の段階表示。
- `cg.visualize_data()` 互換の単一JSON履歴の自動保存と、結果画面からのファイル操作。
- 利用者の確認後に限り、JSONを外部の公式ビューワーへPOSTするローカル補助ページ。
- 既定 1440×900、物理 1280×720 相当、150%、200% 表示倍率とキーボード操作。
- エージェントを同梱しない one-folder 配布。

## 対戦画面の表示

カードへカーソルを合わせると、右側のカードプレビューへ大きな画像を表示します。

日本語カード画像がある場合、カード本文に含まれる特性、ワザ、効果も画像から確認できます。

ポケモンは現在 HP と最大 HP を数値で示し、ついているエネルギー枚数とポケモンのどうぐを盤面上へ重ねます。

トラッシュは各プレイヤーの右側へ置き、カーソル操作またはクリックで内容一覧を開きます。

AI の行動後は状態更新を先に描画してから、設定した表示時間だけ次の行動を待機します。

合法手のカード名とワザ名は日本語カタログで変換し、対応する翻訳がない場合はエンジンの名称を残します。

サイド取得の匿名候補は `サイド1`、`サイド2` の形式で表示し、裏向きカードの ID や内部位置を表示しません。

サイド番号は物理的な上下位置ではなく、その時点で画面に並ぶ合法手の順番を表します。

カードを対象とする合法手は一覧と盤面へ同じ番号を表示し、選択後はカード全体を金色で示します。

通常の手貼りは「つけるカード → ポケモン」の組み合わせで表示し、カード効果による付与はカード選択とポケモン選択の現在段階を示します。

## JSON履歴

アプリ用の `.ptcgmatch` は、マニフェスト、各メンバーのSHA-256、結果、公開ログ、完全局面を含むZIP形式です。

新規対戦では、エンジンの `visualize_data()` が返した局面配列をリプレイ内へ保持し、検証後に同名の `.visualizer.json` を保存します。

旧形式の `.ptcgmatch` は、検証済みの正規化局面から同じJSON構造を再構成できます。

公式ビューワー用JSONは試合後レビュー用の完全情報であり、双方の手札、山札順、サイド内容を含みます。

補助ページはローカルでJSONを読み込み、利用者が確認ボタンを押した場合だけ `ptcgvis.heroz.jp` へ送信します。

JSONを選んだだけでは外部送信しません。

## MVP に含めない機能

オンライン対戦、リプレイの公開共有、Kaggle への提出、エージェントの編集や学習、AI の内部評価や選択理由表示は対象外です。

シード指定による完全再現、中断局面からの再開、デッキ編集、対戦履歴集計、自動診断は対象外です。

カード画像の同梱、リプレイへの画像埋め込み、ネットワークからの画像取得は行いません。

任意コードを制限付き Windows アカウントや仮想マシンで実行する OS サンドボックスも対象外です。

## 表示の意味

**Verified Submission** は、ローカルの全ファイルがアプリ内の固定マニフェスト `submission-55155015-v1` と一致したことを示します。

「Verified Submission」は Kaggle の Linux コンテナー環境まで同一であることを保証しません。

**自己管理ローカルエージェント** は、利用者が明示的に登録したファイル構成と SHA-256 に現在の内容が一致し、起動互換性確認を通過したことを示します。

「自己管理ローカルエージェント」は Kaggle 提出物との同一性、コードの安全性、全局面での正常動作を保証しません。

人間デッキの表示は、`60枚構成確認済み`、`両座席でエンジン受理確認済み`、`大会レギュレーション未検証` を独立して扱います。
