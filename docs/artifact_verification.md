# エージェントの識別と検証

## 二つの識別区分

アプリは、固定提出物と自己管理ローカルエージェントを別の区分で扱います。

**Verified Submission** は、アプリに固定した `submission-55155015-v1` マニフェストと全ファイルが一致した場合だけ使用します。

**自己管理ローカルエージェント** は、利用者が選択して登録したパッケージのファイル指紋と現在の内容が一致する場合に使用します。

ローカル登録を submission 55155015 の本人性証明へ昇格させることはできません。

## ローカル登録

ファイル選択だけでは `main.py` や `cg.dll` をロードしません。

利用者が「この内容を登録して互換性を確認」を実行すると、アプリはパッケージ内の全通常ファイルについて、相対パス、バイト数、SHA-256 を記録します。

内容指紋は、エントリーポイント `main:agent`、作業ディレクトリ、並べ替え済みファイル記録を正規化 JSON にした値の SHA-256 です。

同じファイル集合を持つアーカイブと展開フォルダーは同じ内容指紋になります。

アーカイブ入力では、再圧縮やアーカイブメタデータの変更も検出するため、アーカイブ全体の SHA-256 も登録します。

登録は現在のアプリ実行中の対戦準備に対して有効です。

選択パスは設定へ保存しますが、アプリを再起動した後は互換性確認を再実行します。

## パッケージ契約

実行ルートには `main.py`、`deck.csv`、`cg/__init__.py`、`cg/api.py`、`cg/sim.py`、`cg/utils.py`、`cg/game.py`、`cg/cg.dll` が必要です。

`main.py` は呼出可能な `agent(obs)` を定義し、`deck.csv` は 60 件のカード ID を持つ必要があります。

アプリは `requirements.txt` を実行せず、依存パッケージをインストールしません。

外側の管理用フォルダーや ZIP を選んだ場合、内側の実行ルートを推測せず不適合として停止します。

## 安全な読取りと展開

登録対象は最大 1,024 エントリーかつ 512 ファイル、アーカイブ最大 512 MiB、1 ファイル最大 256 MiB、展開合計最大 512 MiB です。

アーカイブでは、絶対パス、親参照、シンボリックリンク、ハードリンク、デバイス、重複名、Windows で大文字小文字が衝突する名前を拒否します。

展開フォルダーでは、シンボリックリンクとジャンクションを拒否します。

Windows の予約名、末尾の空白またはピリオド、コロンを含むパス要素も拒否します。

アーカイブは登録済みファイル集合だけを専用一時領域へ展開します。

## 起動までの再検査

登録後、アプリは専用ステージングへファイルをコピーし、ステージング上の全ファイルを同じマニフェストで再検査します。

次に、使い捨てワーカーが同じマニフェストを検査してから `main.py` とエンジンをロードし、人間デッキを両座席で `battle_start` へ渡します。

対戦開始時にはソースから新しいステージングを作るため、互換性確認後にソースが変わっていれば開始を拒否します。

対戦ワーカーもロード直前にステージングを再検査します。

## 同一性と安全性の限界

固定提出物の検証は、ローカルバイトが保管された submission 55155015 と一致することを判定します。

この検証は Kaggle 実行時の Python、Linux コンテナー、CPU、システムライブラリまで同一であることを保証しません。

ローカル登録は、登録した時点のバイト列との一致を判定します。

ローカル登録は、コードの安全性、Kaggle への提出履歴、全局面での正常動作を保証しません。
