# セキュリティ境界

## 保護対象

対戦中の AI 手札の内容、両者の山札順、未公開サイドの内容、AI 側の選択肢、選択理由、スコア、完全観測を保護対象とします。

通常 UI、QML ViewModel、IPC、公開ログ、通常エラー、stdout、stderr のいずれにも保護対象を流しません。

## 信頼境界

エンジン、提出エージェント、生観測、`visualize_data()`、`FullReplayFrame` は対戦ワーカー内の特権領域に置きます。

GUI は `HumanViewState`、`DecisionRequest`、公開ログ、結果、封印済みリプレイのパスだけを受け取ります。

`visualize_data()` は両手札、両山札順、サイド内容、裏向きのセットアップポケモン、選択済みインデックスを含むため、そのまま IPC に渡すことを禁止します。

## 投影原則

`HumanViewState` は新しい辞書としてホワイトリスト生成し、元辞書の副作用的な削除や QML の `visible: false` を秘匿手段にしません。

人間手札は完全情報から回復してもよい唯一の非公開ゾーンですが、所有者、枚数、カード ID の整合性を毎回検査します。

対戦相手の手札は枚数だけを表示し、両者の山札順とサイド内容は表示しません。

対戦相手のセットアップ用ポケモンはターン 0 で常に裏向きとし、人間の通常観測で公開されるまで実体を表示しません。

`looking` の実体は、通常観測の選択者が人間席で、通常観測自体が実体を持つ場合だけ表示します。

## 法的手の境界

`DecisionRequest` は通常観測からだけ生成し、各選択肢をランダムな不透明トークンに対応付けます。

GUI はトークンと表示用ラベルしか受け取らず、生 option、serial、エンジンインデックスを受け取りません。

ワーカーは request ID、state revision、トークンの一意性、選択数、順序、重複、古い要求を検査した後だけ `list[int]` へ復元します。

未知の select type または option type は安全な代替表示のまま進行せず、フェイルクローズします。

## IPC とプロセス

アプリケーションメッセージは `send_bytes` と `recv_bytes` でサイズ制限付き UTF-8 JSON として送受信します。

`send`、`recv`、`Queue`、`Manager` による任意 Python オブジェクトの送受信を禁止します。

Python spawn の信頼済み起動メタデータは実装内部で pickle を使うことがありますが、アプリケーションペイロードに pickle は使いません。

各対戦は新しい spawn 子プロセスで実行し、Windows Job Object の `KILL_ON_JOB_CLOSE` で子孫プロセスを含む異常終了に備えます。

## 脅威モデルの限界

本 MVP は通常の UI、ログ、IPC、エラー表示経路からの偶発的な情報漏えいを防ぎます。

管理者権限のメモリ解析、デバッガー、コード注入、ローカルファイルの意図的な直接解析は保護対象外です。

## 自己管理ローカルエージェント

ファイル選択と指紋計算は、選択した Python コードまたは DLL を実行しません。

明示的な互換性確認では、使い捨て子プロセスが `main.py` を import し、`cg.dll` をロードします。

この子プロセスは利用者と同じ Windows 権限を持ち、OS のセキュリティサンドボックスではありません。

したがって、選択したコードは、利用者がアクセスできるファイル、ネットワーク、プロセス起動機能へアクセスできます。

Windows Job Object は子プロセスと子孫の終了を管理しますが、実行中のアクセス権を制限しません。

アプリのローカル登録は改変検知のための仕組みであり、コード審査や安全性判定ではありません。

利用者が自分で管理し、内容を確認したパッケージだけを登録対象とします。
